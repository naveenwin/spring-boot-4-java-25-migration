# 99 — Anti-patterns

Numbers are stable; phase docs cite them. The orchestrator reads **Cross-cutting** once. A verifier reads Cross-cutting plus the rows that name its phase.

## Cross-cutting

1. **Half Jackson** — Running Boot 4 application JSON through `spring-boot-jackson2`, keeping `spring.jackson2.*`, deferring Jackson 3 “for later,” or rolling back only the mapper to preserve a payload. Boot 4 + Jackson 3 is one hard cutover; preserve compatibility with the Stage 0 wire baseline and explicit Jackson 3 features, not a bridge.
6. **Copying another service** — Opening sibling repos for “how they migrated.” Apply these docs to the service root only.
7. **Global JDK flip** — Changing a developer’s default SDK from 21→25 for all projects without asking. Use per-command `JAVA_HOME` instead.
8. **Mega-commit** — One commit spanning several phases. Stage A is one commit per owning phase; Stage B commits carry one phase id ([COMPILE-GATES.md](COMPILE-GATES.md)). A commit subject without `<phase-id> <A|B|fix>:` cannot be attributed.
9. **Wrong gate for the stage** — Expecting a green compile in Stage A, or a context load in Stage B. Stage A gates on configure + resolve; Stage B gates on zero owned compile errors; only Stage C runs the context and suite ([COMPILE-GATES.md](COMPILE-GATES.md#stage-gates)). Running the full suite between Stage B phases is theater. Fixing another phase's owned errors to "get green" is the domino this flow exists to stop.
21. **Wrong Cloud train** — Pairing Boot 4 with Spring Cloud **2025.0.x** (Boot 3.5-only) instead of **2025.1.x**.
23. **Blind JVM opens** — Adding `--add-opens` / unsafe-memory flags without a captured library failure and a removal condition.
25. **Compile-only “done”** — Declaring the migration complete when only compile is green, or without a Stage C delta against the baseline (`newlyFailing=0`, every `missing` explained).
28. **Self-certified claim** — Marking a claim `observed` without a quoted source, or `run` without a run id. Compile and runtime claims stay `unverified` until a run supports them ([CONTEXT-CONTROL.md](CONTEXT-CONTROL.md)).
29. **Log in the parent context** — Reading `raw.log`, `summary.json`, or an errors/tests tsv in the orchestrator chat, or pasting those rows into a capsule. The orchestrator keeps the extractor's one-line summary. It runs Gradle or Maven with output redirected into the run directory. The worker reads its own rows from disk. Stage C failures go through the log triager ([LOG-TRIAGE.md](LOG-TRIAGE.md)). A fifth build run in the same chat is the same violation: write the handoff first. Running the full test suite, or running a build without redirecting its log into the run directory, is the same violation. Fixing a downstream phase from a stale run after an upstream fix is the same violation.
30. **Fixing in a polluted chat** — Continuing after a hard reset trigger (pasted log, stage gate passed, four build runs, two fix rounds on one cause, file-vs-memory conflict) without writing `handoffs/` and asking for a new chat ([CONTEXT-CONTROL.md](CONTEXT-CONTROL.md#chat-reset--new-chat-handoff)).
31. **Planning past catalog gaps** — Approving or executing a plan while must-relevant stubs are still stubs, while `blocksPlan` gaps are open, or while the migrate agent edits the fleet `DEPENDENCY-CATALOG.md` / invents non-allowlisted versions ([CATALOG-GAP.md](CATALOG-GAP.md)).
32. **Transitive catalog scan** — Walking the full resolved dependency tree during preflight “to be thorough.” Declared pins and plugins only; the resolve run and triage handle late skew ([CATALOG-GAP.md](CATALOG-GAP.md)).
36. **Unbounded doc fishing** — Open-ended WebSearch/GitHub/Maven sessions during execute, or browsing before the ladder in [COMPILE-GATES.md](COMPILE-GATES.md#bounded-external-lookup). Bounded lookup (≤2 calls, official sources, pack gap recorded) is allowed; re-researching a catalog pin is not.
37. **Guessing past a blocker** — Implementing a slice while the item has an `open` blocker, or closing a blocker without an answer from the repo, the human, or a bounded lookup ([CONTEXT-CONTROL.md](CONTEXT-CONTROL.md#readiness)).
41. **Jargon at the human** — Telling the human "Stage A", "phase 35", or a bare id as if they should know the pack. Say what is happening in ordinary words first; keep file ids in YAML, commits, and parentheses ([SKILL.md](../SKILL.md#speak-to-humans)).

## Phase-specific

2. **Wrong OpenAPI flag story** — Keeping `useSpringBoot3` on a Boot 4 service when the generator supports `useSpringBoot4` / `useJackson3` (05).
2a. **Wrong springdoc / Knife4j train** — Running springdoc **2.x** or Knife4j **Jakarta/Boot3** starter on Boot **4**; inventing `ControllerAdviceBean` shims; reverting the whole app to `spring-boot-jackson2` only to quiet swagger-core’s Jackson 2 introspection; or treating runtime docs as a substitute for generator flags ([32-springdoc-openapi.md](../phases/32-springdoc-openapi.md)).
3. **Unversioned `feign-jackson3`** — Adding it when the BOM does not manage Feign that ships that module (06).
4. **protoc leapfrog** — Jumping `protoc` 3.21 → 4.x without pinning matching `protobuf-java` (+ util if used) and regenerating (15).
5. **Silent lock rewrite** — Changing lock key/TTL/refresh semantics inside the Boot bump (including while fixing TaskScheduler wiring), or replacing the library when a Boot 4–compatible major of the same coords exists (e.g. alturkovic `distributed-lock-jdbc` 3.0.0). Also leaving `spring-boot-starter-aop` on Boot 4, staying on aggregate `1.5.x` + excludes when the jdbc module exists, omitting TaskScheduler `@Primary` after a multi-scheduler context failure, or never declaring `starter-aspectj` when annotation locks need it (11).
10. **Map-shaped HttpHeaders** — Treating Framework 7 `HttpHeaders` as a permanent `Map`/`MultiValueMap` API. Prefer overloads that accept `HttpHeaders` (`containsHeader`, `getFirst`, `headerNames`). A short-lived `asMultiValueMap()` bridge is compile-only tech debt — do not leave it as the end state (06).
11. **Cucumber version-only bump** — Shipping Cucumber 8 jars while keeping unused `cucumber-java8`, static `WireMock.configureFor`, and a mega package glue scan. Modernize glue/hooks or do not claim Cucumber 8 (16).
12. **WireMock version skew / curl-only CI** — Client on 3.13.x while CI/docker stay on an older 3.7.x, staying on `org.wiremock:wiremock` while CI expects `wiremock-standalone`, or downloading the standalone JAR with `curl` on images that do not ship curl. Align 3.x via Gradle-resolved copy; defer WireMock **4** while beta (12, 16).
13. **Faker-flaky success tests** — Asserting `SUCCEEDED` while faker can leave payment amount `0` or status `IN_PROGRESS` so async processing is skipped. Half-fixing one test while shared generators stay random counts as this anti-pattern (09).
14. **Wrong phase for Hypersistence** — Bumping `hypersistence-utils-hibernate-55`/`63`/`71` → `73` inside the lagging dependency queue instead of the Hibernate phase ([03-hibernate-7.md](../phases/03-hibernate-7.md)). TypeDef/`@JdbcTypeCode`/merge/Session API work belongs in phase 03, not the queue.
15. **Stale `@MockBean`** — Keeping Boot 3 `@MockBean` after Boot 4 cutover instead of `@MockitoBean` (09).
16. **Cucumber/unit race** — Running Cucumber in the same parallel Test worker or CI job as unit tests that share DB, WireMock, or messaging emulators (09, 16).
17. **Hypersistence `update` on H7** — Leaving `BaseJpaRepository.update` on versioned managed entities after Hibernate 7 / Hypersistence 73 (prefer `merge`) (03).
18. **Custom UUID generator revival** — “Fixing” assigned-UUID inserts by reintroducing `CustomUUIDGenerator` / `@GeneratedValue` instead of `Persistable.isNew` when IDs are application-assigned (03).
18a. **Hibernate off-BOM pin** — Forcing `hibernate-core` ahead of/behind the Boot BOM (e.g. 7.3 on Boot 4.0) without an approved spike; Boot owns 7.2 (4.0) / 7.4 (4.1) (03).
18b. **Legacy Session API on H7** — Leaving `Session.save` / `update` / `saveOrUpdate` / `delete` / `load` or Hibernate `@Where` / `@LazyCollection` after the H7 cutover (removed — use `persist`/`merge`/`remove`/`getReference` and `@SQLRestriction`) (03).
18f. **Timezone property as a column fix** — Setting `hibernate.timezone.default_storage=NORMALIZE` or `hibernate.jdbc.time_zone` so validation passes. `NORMALIZE` writes with the JVM zone, and a pod in another zone stores shifted timestamps in the same column ([03-hibernate-7.md](../phases/03-hibernate-7.md)).
18c. **DDL to silence Hibernate** — Changing Flyway/production schema solely to clear H7 validation/DDL-default diffs without human approval ([08-flyway-db.md](../phases/08-flyway-db.md)).
18d. **Stale `hibernate-jpamodelgen`** — Leaving `hibernate-jpamodelgen` (especially pinned to 6.x) after Boot 4 so metamodel `*_` classes silently stop generating ([33-jpa-spring-data.md](../phases/33-jpa-spring-data.md)).
18e. **`getOne` / native.parser on SDJPA 4** — Keeping `JpaRepository.getOne`/`getById`/`deleteInBatch`, or relying on removed `spring.data.jpa.query.native.parser` (silently ignored) instead of `getReferenceById` / `QueryEnhancerSelector` ([33-jpa-spring-data.md](../phases/33-jpa-spring-data.md)).
19. **Classic forever** — Leaving `spring-boot-starter-classic` / `test-classic` as the permanent end state with no exit to focused starters ([19-modular-starters.md](../phases/19-modular-starters.md)).
20. **Migrator left on** — Shipping `spring-boot-properties-migrator` to production instead of fixing keys and removing it ([18-config-properties.md](../phases/18-config-properties.md)).
22. **CSRF off to green tests** — Disabling CSRF as a generic Boot 4 / Security 7 fix instead of matching the client model (20).
24. **Java 21 pinning advice on 25** — Mechanically replacing `synchronized` with `ReentrantLock` for virtual-thread pinning on Java 24+ without diagnostics.
26. **GCP emulator confidence inflation** — Treating a Pub/Sub/Secret Manager fake or emulator as proof of ADC, Workload Identity, TLS, or IAM; disabling bootstrap/import/auth to make Boot 4 start; or leaving `sm://` deprecation unplanned ([34-spring-cloud-gcp.md](../phases/34-spring-cloud-gcp.md)).
27. **Vintage as the Boot 4 test fix** — Adding `junit-vintage-engine` or `junit:junit` so JUnit 4 tests keep running, pinning `junit-jupiter` 5.x or Platform 1.x over the Boot 4 BOM, pinning a 6.1.x patch ahead of the BOM, or finishing on `junit-jupiter-migrationsupport`. Skipping [36-junit-jupiter.md](../phases/36-junit-jupiter.md) because sources already use `org.junit.jupiter` leaves that pin in place. A green `useJUnitPlatform()` run with JUnit 4 classes still in `src` means those tests were not discovered (the Stage C delta shows them as `missing`). The close gate requires Boot-managed JUnit 6 (**6.0.3** on Boot **4.1.1**).
33. **Editing CI or runtime images** — Changing job `image:` lines, Docker `FROM`, Jib base images, or registry tags during the migration. This pack does not ship image defaults. The JDK for an agent build is `JAVA_HOME` on the pinned command ([37-gitlab-ci.md](../phases/37-gitlab-ci.md)).
34. **Silent keep of remove-listed libs** — Bumping `io.vavr` to 1.x or `johnrengelman.shadow` 8.1.1 in phase 12 without [38-remove-vavr](../phases/38-remove-vavr.md) / [39-remove-or-migrate-shadow](../phases/39-remove-or-migrate-shadow.md) analysis + risk score; adding `vavr-jackson` to paper over Jackson 3; or replacing Vavr with another FP library ([DEP-REMOVAL.md](DEP-REMOVAL.md)).
35a. **Kotlin 2.2 JVM 24 as Java 25 end state** — Leaving Kotlin **2.2.x** with `jvmTarget` / Java compatibility capped at **24**, or calling `JvmTarget.fromTarget("25")` on **2.2.x**, while the contract is JDK **25** on Boot **4.1**. `fromTarget("25")` does not extend the **2.2** compiler; configure still rejects target **25**. Upgrade to Kotlin **2.3.21** and `JvmTarget.JVM_25` ([31-kotlin.md](../phases/31-kotlin.md)).
35b. **Awaitility pin ahead of Central / BOM** — Phase-12 bumping `org.awaitility:awaitility` to a catalog patch that Maven Central does not publish yet, instead of omitting the version and using the Boot BOM ([12-dependency-bump-queue.md](../phases/12-dependency-bump-queue.md)).
35c. **JUnit 4 kept for MockWebServer** — Keeping `junit:junit` in any form (`testImplementation`, `testCompileOnly`, a dropped exclude) or legacy `com.squareup.okhttp3:mockwebserver` 5.x as the Boot 4 end state. OkHttp 4.x and legacy mockwebserver **5.5.0** both extend `ExternalResource`; the 5.5.0 POM still depends on `junit:junit:4.13.2`; `testCompileOnly` compiles and then throws `NoClassDefFoundError` at runtime. Phase 28's Stage A slice swaps in `mockwebserver3` in the same wave that removes `junit:junit`.
35d. **GCP 8 with protoc 3.x** — A Stage A wave that moves Spring Cloud GCP to 8 while `protobuf-java` / `protoc` stay on **3.x** with Pub/Sub codegen present. Pub/Sub auto-config then fails at `RuntimeVersion$RuntimeDomain` in Stage C. Phase 15 is `must` in that case and its A slice bumps the pin in the same wave ([PHASE-CATALOG.md](PHASE-CATALOG.md#conditional-priority-the-only-place-these-rules-live)).
35e. **`mockwebserver3-junit5` on Boot 4** — It pins `junit-jupiter-api` 5.13.4 against Boot's JUnit 6. Use `mockwebserver3` alone ([28-okhttp-5.md](../phases/28-okhttp-5.md)).
35f. **Duplicate `@ExceptionHandler` on `ResponseEntityExceptionHandler`** — `@ExceptionHandler(NoResourceFoundException::class)` (or other base-class types) on a `@ControllerAdvice` that extends `ResponseEntityExceptionHandler` prevents context startup. Override `handleNoResourceFoundException` / `handleTypeMismatch` / `handleMethodArgumentNotValid` instead, and only after the phase 09 `ASK_HUMAN` body-contract decision. Do not replace ProblemDetail with an empty body on the `SAFE_AUTO` path ([09-testing.md](../phases/09-testing.md)).
35h. **404 swallowed as 500** — An `@ExceptionHandler` for `ServletException` or `Exception` that handles `NoResourceFoundException`. The client receives 500 and probe traffic logs a stack trace. The 404 keeps its own outcome ([09-testing.md](../phases/09-testing.md)).
35g. **Nullable `findByPath` task dependency** — `dependsOn(tasks.findByPath("…"))` in the Kotlin DSL. `findByPath` returns `Task?` and configure fails. Use `dependsOn("name")` or `tasks.named("name")` ([12-dependency-bump-queue.md](../phases/12-dependency-bump-queue.md)).
38. **Silent Pub/Sub lease** — Leaving `max-ack-extension-period` unset when the source Spring Cloud GCP is below **6**, which changes ack extension from 0 seconds to the client default of 60 minutes. Setting `0` or adopting 60 minutes without a recorded choice is the same mistake. The 8.2.4 javadoc still says the default is 0; the code does not ([43-pubsub.md](../phases/43-pubsub.md)).
39. **Raw Pub/Sub ObjectMapper** — `new ObjectMapper()`, a Jackson 2 type, or a second `PubSubMessageConverter` bean on Boot 4. Auto-config wires a converter only when it is unique, and a raw mapper ignores Boot's `JsonMapper` ([43-pubsub.md](../phases/43-pubsub.md)).
40. **Pub/Sub health indicator injection** — Injecting `PubSubHealthIndicator` after GCP 8, which registers `pubSubHealthContributor` and always wraps it in a composite. Mocking the old type does not stop the real pull ([43-pubsub.md](../phases/43-pubsub.md)).
42. **Health group validation off** — Setting `management.endpoint.health.validate-group-membership=false`, or retargeting a readiness probe, so a group that names a missing contributor still starts. Fix the group. The default readiness group is only `readinessState` ([22-actuator.md](../phases/22-actuator.md)).
43. **HTTP client swapped in silence** — Adding `httpclient5` without recording that every `RestTemplate` and `RestClient` changes implementation, or installing a redirect strategy so a 301/302 stops turning POST into GET, without a human decision ([06-http-clients.md](../phases/06-http-clients.md)).
44. **Silent task-executor alias or pool** — Registering a `taskExecutor` alias, or writing `spring.task.scheduling.pool.size` / `spring.task.execution.pool.*` to a size the service did not already set, without a recorded human decision. Enabling `spring.threads.virtual.enabled` to make those pool keys apply is the same mistake ([45-task-execution.md](../phases/45-task-execution.md)).
